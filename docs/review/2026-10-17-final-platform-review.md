# Independent final review — 2026-10-17 platform branch

Review scope: branch diff `fbd4430..9d1101b` against the approved 2026-10-17 platform specification, implementation roadmap, detailed plans 01–04, and execution ledger. The reviewer completed a read-only audit after the A3 release gate. These are Important findings; they are tracked as release blockers until verified fixes and regressions are recorded.

1. **Important — Email-mode publication always fails, even with a configured sender.** `src/QuestionAppBuilder.Infrastructure/Authoring/DraftService.cs:22` constructs `DefinitionValidator` without passing `emailSenderConfigured`; its default is false. Review and publication therefore produce `email-delivery-unavailable`. Pass the actual capability through both validator construction paths and test successful email publication. Violates spec §9 and E4/R4/U3.
2. **Important — Email grants authorize every response belonging to the email owner.** `src/QuestionAppBuilder.Infrastructure/Responses/ResponseService.cs:180` accepts an owner-key match before checking grant scope; `ListMineAsync` at line 161 enumerates all matching responses. `SubmissionCoordinator.cs:36,108` repeats owner-wide authorization. A grant for response A can discover/read/save/submit response B for the same email, including across applications. Enforce grant scope independently of matching ownership. Violates roadmap prohibition against same-email cross-response access and enumeration.
3. **Important — The host’s FillPolicy is never enforced.** `ResponsesController` has no authorization filter and runtime routes add no authorization metadata. Core DI registers a default `RequireAuthenticatedUser` policy under the requested name, which can overwrite a host policy already registered. A signed-in identity denied by the host’s fill policy can still create and operate responses. Preserve and enforce the configured policy, including conventional routes. Violates spec §3 and U3.
4. **Important — Failed runtime autosaves retry indefinitely without delay.** `src/QuestionAppBuilder.Core/wwwroot/js/runtime.js:43` calls `queueSave(0)` whenever dirty, including after 409, 422, and 503 responses. The `failed` flag does not gate this path. This repeatedly submits stale/invalid data, flashes the error state, and can hammer the server. Stop automatic retries on failure and provide a deliberate retry/conflict path. Violates U1’s reliable save-state contract.
5. **Important — Editing silently carries warning acknowledgments onto a new revision.** `src/QuestionAppBuilder.Editor/wwwroot/js/editor.js:12` updates the publication revision after autosave without clearing checked acknowledgments or refreshing readiness. A designer can acknowledge an overlap, change bounds/points, and publish the new revision with the old checked warning code. Invalidate acknowledgments on edits and require review of the saved revision. Violates spec §4–5 and E4/U2.
6. **Important — The fallback conflict page enables overwriting the competing save.** `src/QuestionAppBuilder.Core/Controllers/ResponsesController.cs:220` combines stale posted answers with the freshly loaded snapshot’s revision. The rendered form can resubmit stale values over the other tab’s changes. Preserve the rejected revision and require explicit reload/conflict resolution. Violates spec §8 and R2/U1 no-silent-overwrite.
7. **Important — Branch changes never update the current respondent screen.** `ResponsesController.Save` returns only revision/time after autosave; `runtime.js` never updates visibility. Same-category dependent questions remain absent/visible until navigation/reload; a newly hidden required control may still block submission through native browser validation, while newly visible questions cannot be answered. Return authoritative visibility/render information and apply it while preserving values and focus. Violates spec §6 and U1.
8. **Important — Email resume links lead to an unusable page after starts close.** `AccessController.Redeem` always redirects redeemed grants to the application landing page. `Views/Responses/Landing.cshtml` hides all actions when new responses are closed, including access to an existing granted response. There is no resume-link request form carrying `responseId`. Redirect response grants directly to their response and expose recovery independently of new-start availability. Violates spec §8–10 and R4 existing-resume-after-stop.
9. **Important — Preview does not provide the required runtime experience or scoring inspector.** `editor.js` discards returned questionnaire, validation issues and rule traces, displaying only total score and visible-question count. Controls in `Views/Drafts/Index.cshtml` are a separate generic answer list, without runtime navigation, conditional rendering, validation, or result modes. Render the actual questionnaire and matching/contributing rule explanation. Violates spec §5 and U2.
10. **Important — Operational availability is inaccessible from the delivered application.** The Applications controller/detail view expose no availability action; `IAvailabilityService` has no UI caller. The host retains the unconfigured trusted-actor fallback. Respondent Review always enables submission without a closed notice. Wire authorized controls, trusted actor attribution, and respondent closed-state presentation. Violates spec §10 and roadmap coverage assignment.
11. **Important — Publication omits the required audit event.** `DraftService.PublishAsync` commits the published version and application pointer without obtaining a trusted actor or inserting `ApplicationAuditEvent`. Only availability changes currently create audit rows. Add publication attribution within the same transaction. Violates spec §4 and E4 step 3.
12. **Important — Reports combine scores across incomparable versions.** `ReportQueries` computes an average across all filtered submissions; Reports index presents it as “Average total,” including mixed-application/mixed-version views. Restrict this metric to one version or remove it from mixed-version views. Violates spec §11.
13. **Important — Respondents review option IDs instead of their answers.** `Views/Responses/Review.cshtml` joins selected IDs rather than resolving option labels. Unanswered optional fields are blank, and categories lack edit links. Render readable choices, explicit unanswered states, and category edit links. Violates spec §8 and U1.
14. **Important — The package-consumer acceptance host cannot exercise real platform endpoints.** `tests/QuestionAppBuilder.PackageHost/Program.cs` registers surfaces but not infrastructure/application services. Its proof controller directly renders empty view models, bypassing packaged controllers and persistence; runtime actions cannot resolve dependencies. Register the packaged platform against disposable SQL and run the required real journey under custom prefixes. Violates A3/spec §3/§12.
15. **Important — The claimed complete release journey is predominantly a fake-service test.** The five-category journey uses a fake runtime. The publication test swaps an in-memory graph without publishing/reloading, the “after close” test never closes submissions, and the email test only requests a neutral response. No connected author→publish→email resume→submit→report/export journey is exercised. Accessibility scans only respondent landing/form screens. Add the specified real-host journey and editor/report accessibility coverage. Violates A3 and spec §12.

Verification distinction: the earlier Editor HTTP 400 was a test-harness parsing defect: Razor HTML-encodes Base64 `+` in the hidden revision value, and the test did not HTML-decode before posting. The new `+w==` regression covers this. The earlier browser 30s timeouts do not establish an application exception or a proven root cause; database-load interference was an inference. A separate missing autosave-status run overlapped a rebuild with VSTest using the same artifacts directory (MSBuild reported the DLL locked); no causal link is established. The final A3 run was otherwise green, but it does not invalidate the independently reproduced Important defects above.

Status: findings reproduced; implementation and regression work is in progress. The path correction below establishes that the earlier A3 browser evidence used the stale project-output SampleHost for artifact-based runs. That earlier browser evidence is not accepted for the corrected host; the full release gate must rerun after all fixes.

# Release verification record

Run `scripts/Test-Release.ps1` with a SQL Server connection string dedicated to testing. The script requires Windows, the .NET 10 SDK (for its package consumer), and Playwright Chromium; it fails before testing when SQL configuration or browser prerequisites are missing. SQL tests create uniquely named disposable databases and drop only those catalogs. Never supply a production connection.

The full solution run includes application/domain behavior, MVC HTTP authorization, SQL migration/concurrency/response/report/export integration, and Chromium journeys. The package step creates all six library packages in a unique local feed, clears package sources except that feed and nuget.org, uses a fresh NuGet cache, and restores a package-only .NET 10 MVC host. It checks packaged compiled views and static assets by HTTP and then runs the actual browser package-consumer test. The package test is intentionally skipped in the preceding ordinary solution invocation because it requires the package host URL; Test-Packages enables it explicitly.

The reporting scale check uses one disposable SQL catalog with 10,000 synthetic submissions and 50 questions, measures overview/page/detail/summary-export/answer-export elapsed time and total managed bytes allocated during the full scenario, and writes SQL Server `STATISTICS XML` for the page query. It is a reproducible observation on the machine/server used for the run, not an SLA or a peak-memory measurement. Preserve the output and `.sqlplan` with release evidence; do not infer production capacity from the synthetic record.

Record for each candidate: commit, SDK/runtime, SQL Server version, exact commands, per-project passed/failed/skipped counts, package version/feed result, browser version, migration-upgrade result, scale dataset/timings/allocation, and plan-file location. Resolve every failed check and explain every skip before release. No external package publication or deployment is performed by these scripts.
